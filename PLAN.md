# Plan: nginx setup

The project name is **Anneal**.

Scope of this file: the URL → file contract and the nginx config that serves it.
How the tree gets produced is `SPIDER.md`.

## 1. URL → file convention

The filename is **the URL path plus the true extension**. Nothing else.

| URL | file on disk |
|---|---|
| `/x` | `x.html` |
| `/x.html` | `x.html.html` |
| `/x/` | `x/_index.html` |
| `/x/index.html` | `x/index.html.html` |
| `/plain.css` | `plain.css.css` |
| `/index.php?bla=whatever` | `index.php?bla=whatever.html` |
| `/theme.php?v=3` (returns CSS) | `theme.php?v=3.css` |

Rules:

- Append the true extension, always. Doubling is normal: `/x.html` → `x.html.html`.
- This is what makes `/x` and `/x.html` distinct. `x.html` is free for `/x`, because
  `/x.html` takes `x.html.html`. No prefix or marker is needed.
- A directory URL gets an `_index.html` inside it.
- The last extension always tells the truth, so `mime.types` sets `Content-Type`.
- URL extension lies about content → `<lie>.<truth>`, e.g. `theme.js.css`.
- Query-string URLs keep the raw request URI: undecoded (`%20` stays `%20`), Linux only.
- URLs over ~250 bytes (over the 255-byte filename limit) → hash
  (`_hash/sha1[0:16].html`) + a `map` entry.
- A URL whose extension lies and whose true type is outside `html/css/js/json` → a `map`
  entry (§2.3).

## 2. nginx

```nginx
http {
    include /etc/nginx/mime.full.types;   # complete map, section 2.1
    types_hash_max_size 4096;             # required for this many types

    # the URL's own trailing extension, so <url>.<ext> can be probed generically
    map $request_uri $ext { "~\.(?<e>[A-Za-z0-9]{1,20})(?:\?.*)?$" $e; default ""; }

    # generated map for URLs the chain below cannot resolve (section 2.3)
    include /etc/nginx/extra.map;

    server {
        listen 80;
        root /srv/static/example.com;
        index _index.html;

        charset utf-8;
        # only the types NOT already in nginx's default charset_types
        charset_types text/css application/json application/manifest+json
                      image/svg+xml;

        gzip on;
        gzip_types text/css application/javascript application/json
                   image/svg+xml application/wasm text/plain application/xml;

        location / {
            try_files $resolved $request_uri.$ext $request_uri.html $request_uri.css
                      $request_uri.js $request_uri.json $uri $uri/ =404;
        }
    }
}
```

One location block. No per-script locations, no `default_type`, no reserved namespace.

Behaviour:

```
/x                           200  text/html    x.html
/x.html                      200  text/html    x.html.html
/x/                          200  text/html    x/_index.html
/x/index.html                200  text/html    x/index.html.html
/theme.php?v=3               200  text/css     theme.php?v=3.css
/plain.css                   200  text/css     plain.css.css
/img.png                     200  image/png    img.png.png
/nope                        404
```

`&`, `=`, `?` are ordinary characters in the filename. A URL with two params is
matched exactly, not truncated.

### What each candidate is for

| candidate | purpose |
|---|---|
| `$resolved` | explicit override from `extra.map` (§2.3) |
| `$request_uri.$ext` | any honest extension: `/img.png` → `img.png.png`, in one `stat()` |
| `$request_uri.html` etc. | URLs whose apparent extension lies: `/theme.php?v=3` → `$ext` is `php`, but the true type is `css` |
| `$uri $uri/` | last resort; `$uri/` is what serves a directory URL |

### 2.1 MIME types — complete map

`nginx/mime.types` is a full replacement for the stock file: **1574 extensions /
1225 types**. Deploy it as `/etc/nginx/mime.full.types` and include it **instead of**
the stock `mime.types` (including both produces `duplicate extension` warnings).

```nginx
include /etc/nginx/mime.full.types;
types_hash_max_size 4096;
```

`types_hash_max_size` is not optional with this many types: the default 1024 logs
`could not build optimal types_hash` and degrades every lookup. 4096 is clean
(measured; `types_hash_bucket_size 128` also works).

Generated by `nginx/gen-mime.py` from, in priority order:

1. **stock nginx `mime.types`** — so nothing that already worked changes. Verified:
   no stock extension lost, no stock MIME value changed.
2. **a modern supplement** — correct current values where the system lists lag:
   `ttf otf ttc`, `mjs cjs`, `map`, `zst lz4 br`, `avifs jxl heic heif jp2 jpx ktx2`,
   `glb gltf usdz stl obj`, `vtt srt`, `yaml toml`, `oga opus wav flac aac weba`,
   `cbz cbr djvu azw mobi`, `torrent crx apk`, `sqlite3 parquet avro graphql ipynb`,
   `mpd m3u8`, `geojson topojson`, `ts tsx jsx scss sass less styl`.
3. **`/etc/mime.types`** (Debian/IANA, ~1500 extensions) — the long tail: CAD, GIS,
   chemical, medical, legacy office, telecom, fonts, etc.

Coverage checks run against it: 40 extensions present in stock nginx are absent from
`/etc/mime.types` (wap, java, kml, xspf, …) — carried over. 70 sampled extensions
across categories all resolve; none fall through to `octet-stream`.

Re-run `python3 nginx/gen-mime.py` after adding entries, then `nginx -t` — a
`duplicate extension` warning means an entry is already mapped elsewhere.

**A `types` block in `http` MERGES with an included map; in a `location` it REPLACES
it.** That is why the complete file must be included at `http` level and not
supplemented inside a `location`.

Check the config with stderr visible: nginx reports `duplicate MIME type` warnings on
**stderr at startup**, not in the error log, so they vanish under `2>/dev/null`:

```
nginx -t 2>&1 | grep -i warn
```

Never publish `.pem/.crt/.der/.p12/.pfx` (they are mapped as certificates):

```nginx
location ~* \.(pem|crt|der|p12|pfx)$ { return 404; }
```

### 2.2 Lookup order (breaks silently)

The extension probes must come **before** `$uri $uri/`. In that order `/x` hits `x.html`
on the first candidate and never reaches `$uri/`, so there is no 301 to `/x/`.

Reverse it to `try_files $uri $uri/ $request_uri.html …` and every slashless page 301s
to its directory instead. Measured: `$uri $uri/` alone gives `/x` → 301, `/x/` → 200.

`$uri $uri/` must stay at the end, or `/x/` returns 404.

### 2.3 `extra.map` — explicit overrides

A handful of URLs cannot be resolved by the chain: the URL's apparent extension lies
**and** the true type is outside the probed four (`html/css/js/json`). Example:
`/thumb.php?id=5` returning a PNG.

Each one gets a line in `extra.map`, which `include`s at `http` level:

```nginx
map $request_uri $resolved {
    default "";
    "/thumb.php?id=5"  /thumb.php?id=5.png;
}
```

The key is **`$request_uri`, never `$uri`** — `$uri` has the query string stripped, and
every such case has a query string. Get this wrong and the entry silently never matches.
The file may be empty (`default ""`).

## 3. Redirects

Where two URLs served the same body, keep one file and collapse the other:

```nginx
location = /x.html { return 301 /x; }
```

301s are cached by browsers indefinitely, so fix the canonical direction before launch.

Caveat: `try_files $resolved …` probes `$resolved` first, so an override in `extra.map`
always wins. Keep the map free of URLs you also redirect.
